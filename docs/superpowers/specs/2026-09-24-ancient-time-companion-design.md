# 古代计时美学 App：Android 首版需求草案

**状态：产品草案已确认；Android 首页已按最新视觉稿实现并完成构建验证。**

## 产品定位

一款离线优先的古代计时美学陪伴 App。主体验是安静地看时辰、读一行诗；采用宋式清雅视觉：温纸白、淡墨、低饱和青绿、细刻线与充足留白。首页保持简洁，日期和历法信息进入次级页面。

## 首版页面与流程

1. **首页时辰盘**：十二时辰为主刻度，显示当前时辰和一行诗句。每个时辰内以八段浅刻度表现九十六刻制。点选其他时辰时，中心切换为该时辰预览，同时保留“此刻”标记；可继续进入时辰笺。
2. **时辰笺**：时辰名、别称、现代时间范围、生活意象、诗句及出处；地支和生肖作为次要信息。首版不提供每日宜忌。
3. **日期详情**：显示今日干支和当前节气。首页不常驻显示完整历法信息。
4. **仪式计时器**：提供“一刻（15 分钟）”“一炷香（30 分钟）”“半个时辰（60 分钟）”预设，并明确显示分钟数。支持开始、暂停、继续和重置；离开 App、锁屏或设备重启后计时状态恢复，结束时发系统提醒；钟磬音效可选，默认静音。首次开始计时并需要后台提醒时，再说明并申请所需权限；拒绝精确提醒权限后仍继续计时，但系统提醒可能延迟；拒绝通知权限时保留 App 内完成状态。

## 首页视觉与交互细节

- **最新视觉稿（2026-09-25）覆盖本节早期构想中的中心文字排布与浅色配色。** 首页以 `outputs/home-2026-09-25-object/home.html`、`small-screen.html` 和同目录 PNG 为实现基准；如早期文字描述与稿件不一致，以该视觉稿为准。
- 全屏使用近黑底 `#0F0E0D`、克制金色 `#D9A94B`、青绿预览色 `#7FBFA4` 与灰米色文字。整体采用宋体/衬线字形和细线，保留安静、清简和留白。
- 圆盘是主视觉。盘心只保留实时晷针、淡金投影和轴心，其他区域留白；晷针按本地时间在 24 小时内连续旋转一周，每两小时推进 30°，指示当前时辰内的位置。时辰名、读数、诗句和现代时间范围均显示在圆盘外。
- 盘面由十二地支、二十四个“初/正”刻字、十天干环字和九十六道刻线构成。刻线低对比度、长短有节奏；不另加厚重边框或密集辅助说明。
- 当前真实时辰始终由外圈细金弧 `#D9A94B` 标出。预览另一时辰时，仅在其扇区叠加克制的青绿 `#7FBFA4` 高亮；金色弧线和晷针仍跟随真实时间，不跟随预览。
- 当前时辰名、别称、刻读数、诗句及对应现代时间区间排在表盘下方。预览时将当前分钟映射到所选时辰的起始小时，例如当前为 00:18、预览巳时则显示 09:18；更点提示仍使用真实当前时间。
- 仅当真实时间处于 19:00–05:00 时显示“此刻 · 三更四点 · 简化对照”一类提示；其内容不随预览改变。预览状态显示“回到此刻”控件；日期、计时入口留在底部。
- 页面需同时适配视觉稿中的 `393×852` 与 `360×800` 画布。触摸表盘扇区切换预览；跨过真实时辰边界时晷针和金色弧线按真实时间更新，不覆盖当前预览；点“回到此刻”回到最新实时读数。
- 本次 Android 首页实现不展开详情、日期与计时页面；对应入口保留为后续页面入口。

## 首版时间规则

- 十二时辰沿用用户给出的现代时间区间；技术实现建议按设备当前民用时间判定，不作经度修正。
- 今日干支按设备当前时区的本地公历日期离线计算，并在当地时间 00:00 换日；不采用 23:00 子初换日。
- 当前节气使用 App 内置的年度时刻表判断，不依赖网络或定位。数据包至少包含当前年和前一年已发布的年度资料；比较时刻时保留来源时区信息并按绝对时刻处理。年度表以分钟为精度，不宣称秒级交节精度。
- 节气资料按年更新。设备日期超出数据包覆盖范围时，节气显示“资料暂不可用”；今日干支仍按本地日期计算，不用长期公式猜测节气。紫金山天文台说明，长期推算的节气时刻可能有分钟级偏差，因此首版以近期年度资料为准。[紫金山天文台历书资料目录](https://pmo.cas.cn/xwdt2019/kpdt2019/202203/t20220309_6386774.html)；[历书精度说明](https://pmo.cas.cn/xwdt2019/kpdt2019/202203/t20220317_6399980.html)
- 刻度采用九十六刻展示规则：一刻十五分钟，每个两小时的时辰八刻。该规则代表选定的历史计时口径，不宣称适用于所有朝代。[中国国家博物馆：日晷](https://www.chnmuseum.cn/zp/zpml/kgfjp/202110/t20211029_251999.shtml)；[故宫博物院：计时制度资料](https://www.dpm.org.cn/Uploads/pdf/2235/T00043_00.pdf)
- 初、正在一个时辰内分别表示前后两段。
- 夜间更点首版采用十九时至次日五时的现代简化对照：五更、每更五点，共二十五点，每点二十四分钟。界面标注“简化对照”。传统更次会随日落、日出及季节变化；季节性计算留待后续。[故宫博物院：更](https://www.dpm.org.cn/lemmas/244867.html)；[扬州市人民检察院：更点制](https://yz.jsjc.gov.cn/tslm/wenhua/202311/t20231123_917864.shtml)
- “一炷香”在本产品中固定为三十分钟，作为 App 计时预设，不代表各时代统一标准。

## 离线与平台

首发 Android，不依赖账号或网络；诗词、说明、时间映射、今日干支计算和当年节气时刻表可离线使用。Android 原生 Kotlin + Jetpack Compose 为推荐技术路线；界面、时间规则、内容数据、计时通知与音效分层实现。计时器按用户操作场景申请精确闹钟和通知权限，并在权限不可用时提供清楚的降级行为。[Android 精确闹钟说明](https://developer.android.com/develop/background-work/services/alarms)；[Android 通知权限说明](https://developer.android.com/develop/ui/views/notifications/notification-permission)

### Android 平台基线

- 最低支持版本定为 Android 8.0（API 26），兼顾较广设备覆盖与首版维护成本；不支持 Android 7.1 及更早设备。
- `compileSdk` 在正式开工时采用当时最新的稳定 Android API；`targetSdk` 至少满足上架当日 Google Play 的要求。目前（2026-09-24）Google Play 对新应用和更新的最低要求为 API 36（Android 16），所以首版发布目标不应低于 API 36。[Google Play 目标 API 要求](https://support.google.com/googleplay/android-developer/answer/11926878?hl=zh-Hans)
- 不在产品草案阶段固定 Android Gradle Plugin、Kotlin 和 Compose 的具体版本号。实现开工时选兼容的稳定版本，并通过 Gradle version catalog 集中锁定；Compose 库使用稳定版 Compose BOM 统一版本。[Compose BOM 官方说明](https://developer.android.com/develop/ui/compose/bom)
- Android 17 的开发者资料已发布，但在实现时只跟随稳定版 SDK；不为追新预先采用测试版 API。[Android 17 版本说明](https://developer.android.com/about/versions/17)

## 首版不做

精准日晷和 AR、随季节变化的更点、完整年柱/月柱日历、节气倒计时、每日宜忌。日晷意象只用于盘面线条与光影。

## 日期数据校验口径

- 日干支算法按本地公历日期连续推进六十日循环；用紫金山天文台 1900–2025 年历中 1949–2025 年逐日纪日干支核对，并以香港天文台 2026 年历作当前年份交叉核对。[紫金山天文台历书目录](https://pmo.cas.cn/xwdt2019/kpdt2019/202203/t20220309_6386774.html)；[香港天文台 2026 年历](https://www.hko.gov.hk/sc/gts/astron2026/almanac2026_index.htm)
- 换日边界按本地时间 00:00 校验：前一日 23:59 与当日 00:00 属于相邻日干支；23:00 不触发换日。
- 节气边界样例按来源时刻的分钟精度核对：紫金山天文台 2026 年资料列清明为 4 月 5 日 02:40，因此该分钟之前仍为春分，02:40 起为清明。[2026 年日历资料](https://pmo.cas.cn/xwdt2019/kpdt2019/202203/P020251230620718707826.pdf)
- 年界样例：2026 年 1 月 1 日的当前节气应从 2025 年数据中的冬至读取，确认必须随包保留前一年数据。

## 主要实现难点

表盘绘制和预览状态为中等难度；后台计时、通知和音效需处理 Android 生命周期与提醒权限；完整干支历和精准太阳位置计算难度最高，因此安排在后续版本。
