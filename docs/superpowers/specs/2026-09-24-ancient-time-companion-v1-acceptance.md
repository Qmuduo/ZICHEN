# 古代计时美学 App：Android 首版验收清单

**用途：** 在开始 Android 实现前，逐条确认首版用户可见行为与时间边界。本文是产品验收口径，不包含代码或自动化测试实现。

**依据：** [首版需求草案](2026-09-24-ancient-time-companion-design.md)及已确认的时辰盘、日期信息和仪式计时器范围。若本文与需求草案冲突，以较新的明确产品决定为准，并同步修订两份文档。

## 1. 首页时辰盘

- [ ] 首次打开时显示设备当前时辰、该时辰的别称，以及一行固定诗句。
- [ ] 圆盘可辨认地呈现十二个时辰；每个时辰包含八段低对比度刻线，初/正分界线比普通刻线略清楚。
- [ ] 真实当前时辰用淡金细圈标出；预览时辰用浅青绿区分。颜色之外也能辨别当前与预览状态。
- [ ] 圆盘周围不同时铺满十二段现代时间区间；当前或预览时辰的时间范围只在圆盘下方显示。
- [ ] 点选任一时辰后，中心名称、诗句和时间范围同步切换为该时辰；真实当前标记仍跟随设备时间。
- [ ] 预览期间跨过时辰边界，预览内容保持不变，真实当前标记更新到新时辰。
- [ ] 点击“回到此刻”后，中心内容与时间范围恢复为最新当前时辰。
- [ ] 打开时辰笺、日期详情或计时器再返回首页时，保留离开前的预览状态；首次进入时辰笺返回时也保留该时辰。
- [ ] 页面保持宋式清雅和留白；小屏手机上十二个时辰名称、当前标记与主要操作仍清楚可辨，不出现刻线或装饰压过内容的情况。
- [ ] 仅在 19:00–05:00 于时辰范围下方以小字显示真实当前更点，例如“此刻 · 三更三点”，并说明“简化对照”；显示跟随真实时间，不随预览时辰改变，05:00 后隐藏。
- [ ] 日期与计时入口在首页可找到，但不与圆盘争夺视觉中心；首页不常驻展示完整历法信息。

## 2. 时辰、刻与初正边界

按设备当前时区的民用时间判定；一个两小时的时辰分成八刻，每刻十五分钟。该时间刻度是本产品采用的简化口径。

| 本地时间 | 预期读时 |
|---|---|
| 19:00 | 戌时初一刻；简化更点为一更一点 |
| 19:15 | 戌时初二刻 |
| 20:00 | 戌时正一刻 |
| 20:45 | 戌时正四刻 |
| 21:00 | 亥时初一刻；简化更点为二更一点 |
| 23:00 | 子时初一刻；简化更点为三更一点 |
| 23:45 | 子时初四刻 |
| 00:00 | 子时正一刻；日干支按本地日期换日，更点仍属三更 |
| 00:45 | 子时正四刻 |
| 01:00 | 丑时初一刻；简化更点为四更一点 |
| 03:00 | 寅时初一刻；简化更点为五更一点 |
| 05:00 | 卯时初一刻；夜间简化更点结束 |

- [ ] 每个十五分钟边界前后，刻序只前进一刻；整点时辰交界处，时辰、初正和刻序同时切换。
- [ ] 子时覆盖 23:00–次日 01:00；本地 00:00 只切换日干支，不把子时拆成两个时辰。
- [ ] 初、正各覆盖当前两小时区间的一小时：前一小时为初，后一小时为正。
- [ ] 19:00–05:00 使用“五更、每更五点、每点二十四分钟”的简化对照，并明确标注“简化对照”；05:00 后不显示当前更点。
- [ ] 设备时间或时区发生变化后，当前时辰、刻、初正和可见的更点会重新按新的本地时间计算；预览选择不被意外清除。

## 3. 时辰笺

- [ ] 十二个时辰都能从圆盘选择并打开对应时辰笺。
- [ ] 页面依次呈现时辰名与别称、现代时间范围、生活意象、诗句与出处；地支和生肖作为次要信息。
- [ ] 诗句和首页候选保持一致，不随机替换；详情显示作者、篇名和出处，较长内容可滚动。
- [ ] 不显示每日宜忌；文案不把意境配诗说成历史上该时辰专属的诗作。
- [ ] 返回后恢复进入详情前选择的时辰预览。

## 4. 日期详情

- [ ] 页面显示设备本地日期、今日干支和当前节气；不要求账号、网络或位置权限。
- [ ] 日干支按设备当前时区的本地公历日期计算；00:00 换日，23:00 不提前换日。
- [ ] 节气使用随 App 提供的年度时刻资料；比较时考虑来源时区，资料精度为分钟。
- [ ] 数据至少含当前年及前一年的已发布资料；2026-01-01 能使用 2025 年冬至资料判定当前节气。
- [ ] 边界示例：2026-04-05 02:39 显示春分；02:40 起显示清明。
- [ ] 设备日期超出内置节气资料范围时，节气位置显示“资料暂不可用”；今日干支仍正常显示，不以长期推算值冒充精确资料。
- [ ] 断网时日期信息仍可读；时区变化后按新时区的本地日期和时刻重新判定。

## 5. 仪式计时器

- [ ] 提供“一刻（15 分钟）”“一炷香（30 分钟）”“半个时辰（60 分钟）”三个预设；名称和分钟数同时可见。
- [ ] 开始、暂停、继续、重置操作状态明确；暂停时剩余时间不减少，继续后从暂停位置接着计。
- [ ] App 退到后台、锁屏或进程被系统回收后，重新打开时剩余时间和完成状态正确，不从头计时。
- [ ] 设备重启后恢复活动计时：若重启期间尚未到期，重新显示正确剩余时间并恢复提醒；若到期时设备仍关闭，启动后显示已完成，并在通知权限允许时补发完成提醒。
- [ ] 倒计时基于实际经过时长；改变时区不改变到期时刻或剩余时长。
- [ ] 首次需要后台提醒时，先用简短说明解释通知与精确提醒用途，再请求或引导到对应系统权限。
- [ ] 用户拒绝精确闹钟权限后，倒计时仍继续；界面说明系统提醒可能延迟，不显示虚假的准点保证。
- [ ] 用户拒绝通知权限后，不宣称已发送系统提醒；计时完成状态保存在 App 内，用户下次打开时能看到。
- [ ] 用户取消或重置后，旧计时不再触发提醒；结束状态只记录一次。
- [ ] 钟磬音效默认关闭；关闭时结束提醒静音。开启后由系统提醒播放一次本地音效，不依赖网络，也不重复叠播。
- [ ] 飞行模式下预设、计时、状态恢复及本地音效均可用。

## 6. 离线、权限与视觉验收

- [ ] 首版主要体验在飞行模式下可用：时辰盘、时辰笺、诗词、日期资料和计时器均不依赖网络。
- [ ] App 不要求账号、网络或位置权限；只有用户启动需要提醒的计时后，才按需处理通知与精确闹钟权限。
- [ ] 各页面没有空白崩溃状态：缺失节气资料、通知权限关闭、精确提醒不可用等情况都有符合本文的说明或降级表现。
- [ ] 关键状态不只依靠颜色表达；主要触控目标足够清晰，文字与底色保持可读对比。
- [ ] 动效轻缓且不妨碍读时；静态阅读时页面不闪烁，倒计时动画与真实剩余时间一致。

## 7. 已确定的平台与实现基线

- [x] 最低支持版本为 Android 8.0（API 26）。
- [x] 活动计时器在设备重启后恢复；夜间更点以“此刻”次要信息显示在圆盘下方，不改变当前时辰预览。
- [ ] 开始实现前，依据当时 Android 官方稳定发布信息记录 minSdk、compileSdk、targetSdk、AGP、Kotlin 和 Compose 版本；上架时重新核对 Google Play 的目标 API 要求。
