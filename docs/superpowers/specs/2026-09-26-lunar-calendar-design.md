# 农历月历与日期黄历详情设计

**状态：产品设计已确认，等待规格文档审阅。**

**日期：** 2026-09-26

**平台：** Android

## 目标与范围

为现有古代计时 App 增加完整月历和单日详情。用户可浏览公历月份、查看对应农历日期、节气与节日，并查看选中日期的干支及传统黄历内容。功能离线可用，不要求账号、网络或位置权限。

本设计补充并覆盖《古代计时美学 App：Android 首版需求草案》中“首版不做”列出的完整年/月干支日历和每日宜忌范围；时辰盘、时辰笺和计时器的既有规则不变。时辰笺仍不显示每日宜忌。

## 页面与交互

### 月历

- 从首页次要的“日期”入口进入月历；首次打开默认选择设备本地的今天。
- 展示完整公历月，周一为每周第一天。标题显示公历年、月；副标题显示对应农历年与月。
- 月份标题两侧提供前后月切换。选中日期后，日期格高亮，并更新月历下方的日期简介。
- 每个日期格显示公历日和农历日。节气或传统节日当天增加一条短提示，采用已确认的 B「节日提示」布局；格内信息不再增加干支、宜忌等字段。
- 选中日期默认为当日；切换月份后选中该月中与原选择日序相同的日期，若该月没有该日则选月末日期。点击“回到今天”恢复当月并选中今天。
- 点“详情”打开所选日期的详情页；返回后保留当前月份和选中日期。

### 日期简介

月历下方的简介参考用户提供的截图一，包含：

- 农历年月日，以及农历年名和生肖；
- 干支年、月、日信息；
- 星期、当日节气或传统节日（如有）；
- “宜”“忌”两行。

“宜”“忌”内容在 2025-01-01 至 2028-12-31 的离线覆盖期内完整显示。简介只展示短摘要，完整内容在详情页查看。

### 日期详情

详情页参考用户提供的截图二，采用清楚分区、可纵向滚动的布局，包含：

- 农历日期、农历年名/生肖、干支年/月/日和星期；
- 五行/纳音；
- 冲煞信息；
- 彭祖百忌；
- 喜神、福神、财神方位；
- 完整的宜、忌事项；
- 吉神、凶神。

页面底部或内容开头明确标注“传统民俗资料，仅供参考”，并显示资料来源或采用的历法口径。传统黄历的宜忌与神煞不是天文事实，不作为科学结论表达。若某条资料缺失，显示“暂无资料”，不填入推测值。

## 时间与历法规则

- 选中日期以设备当前时区的 `LocalDate` 表示；月份、星期、今天高亮均按设备当前时区处理。不使用地理位置修正日期或时间。
- 既有今日干支在本地 00:00 换日的规则继续用于今日页面。历史日期的干支则根据选中日期计算，不使用当前系统时刻。
- 农历、闰月、节气、节日和干支使用同一份离线历法实现与明确的数据口径；不从网络 API 临时取值。
- 年柱、月柱、日柱、纳音、冲煞、方位和神煞遵循同一黄历引擎所采用的规则。农历年名/生肖与干支年柱作为不同字段处理，避免在立春、农历新年附近把两种边界混为一谈。
- 2025-01-01 至 2028-12-31 为本版完整离线黄历数据保证范围，包含月历所需的农历日期、节气/节日标签和详情字段。
- 月历允许切换覆盖期以外的月份。若离线引擎能提供可靠的农历基础换算，则显示公历日、农历日、星期及可用的基础节气信息；不显示缺少依据的宜忌和神煞，并说明“该年份未包含完整民俗资料”。如果基础换算超出引擎支持范围，则保留公历月历并说明农历资料暂不可用。
- 闰月必须明确显示闰月名称；跨农历新年、公历年、大小月的切换不能错位。

## 数据与实现边界

采用离线日期信息提供层，将 UI 与具体算法库解耦。建议先评估本地 Java 历法库 `lunar-java` 作为农历与黄历字段来源；其公开项目说明包含农历/公历换算、干支、节气、宜忌、彭祖百忌、神煞、方位和冲煞等字段，且项目标注 MIT 许可证：[lunar-java 项目与说明](https://github.com/6tail/lunar-java)。实现前需核实选定版本、许可证文本、Android 兼容性、包体积、日期覆盖范围及各字段输出；若其中任一项无法满足规格，则改用 Android ICU 处理农历换算并为 2025–2028 年打包经过核对的民俗资料。Android ICU 的 `ChineseCalendar` 可供当前 minSdk 26 的设备使用，但它本身不提供本设计要求的完整民俗字段：[Android ChineseCalendar 文档](https://developer.android.com/reference/android/icu/util/ChineseCalendar)。

推荐边界：

1. `LunarCalendarProvider`：按年月提供月历日期格，按公历日期提供农历、节气、节日和干支字段。
2. `AlmanacProvider`：提供纳音、冲煞、彭祖百忌、方位、宜忌、吉神与凶神，并报告字段覆盖状态及口径来源。
3. Android UI 只读取已整理的领域模型，不直接调用第三方库或在 Composable 中计算历法。

候选方案比较：

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 单一本地历法库提供换算和黄历字段 | 离线、规则集中、适合一次生成月历和详情 | 需校验库的边界规则和字段口径 | 推荐，先评估 `lunar-java` |
| Android ICU 换算农历，加 2025–2028 民俗资料包 | 农历换算使用 Android 官方 API，民俗内容可逐条审校 | 年度资料整理与更新工作较多，来源需要维护 | 作为本地库不满足要求时的替代 |
| 在线黄历 API | 数据维护可交给服务端 | 依赖网络和服务稳定性，不符合离线优先 | 不采用 |

传统黄历没有统一的官方宜忌标准。对月相、农历日期和节气等可核对的历法事实，应与可靠年度历书抽样比对；宜忌、吉凶神等民俗字段需固定来源与算法版本，并在界面标注民俗参考，不宣称有单一权威结论。

## 异常与降级

- 无网络：所有已覆盖日期照常显示，页面不显示联网错误。
- 2025–2028 年某项字段缺失：只将该字段标记为“暂无资料”，其他字段继续显示。
- 超出完整黄历覆盖期：保留可计算的月历基础信息，隐藏没有可靠来源的详情字段，并明确提示覆盖范围。
- 不支持的历法日期或数据损坏：显示公历日期和可用资料，不崩溃、不伪造农历或宜忌内容。
- 设备时区变化：按新的本地时区更新今天标记和当前日期；用户正在查看的历史日期不被静默改写。

## 验收标准

- [ ] 首页可进入完整月历；初次打开选中本地今天，月份切换、回到今天及返回状态符合上述规则。
- [ ] 月历每格公历日、农历日正确；节气或节日标签只在对应日期出现，选中日期的简介与详情一致。
- [ ] 2025–2028 年范围内可离线浏览整月，并查看简介和完整黄历字段。
- [ ] 详情包含截图二列出的字段；宜忌、吉凶神和方位有明确来源/口径并标注“传统民俗资料，仅供参考”。
- [ ] 闰月、农历新年、公历年界、月首月末和节气边界经抽样核对；民俗字段固定算法版本并抽样复核。
- [ ] 覆盖期外不会把缺失宜忌或神煞推测后展示；农历引擎不支持的日期会给出清楚降级说明。
- [ ] 小屏上日期简介和详情可读、可滚动；视觉延续宋式清雅与安静简洁风格。
- [ ] 全部数据随 App 本地提供；月历不申请网络、账号或位置权限。

## 暂不包含

不包含个人日程、农历提醒、节日订阅、云同步、黄历个性化、择时/命理建议、日晷与 AR。未来扩展前需另行定义数据来源、准确性口径与用户交互。
