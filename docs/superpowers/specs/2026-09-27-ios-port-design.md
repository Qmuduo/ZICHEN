# Zichen iOS 版设计

**日期：** 2026-09-27  
**状态：** 页面范围、SwiftUI 路线、工程边界和 iOS 16 起步版本已由用户确认；待用户审阅本文档。  
**目标平台：** iPhone，iOS 16 及以上。  
**现有应用：** Android 原生 Kotlin + Jetpack Compose。

## 目标

在现有仓库中增加独立的原生 iOS App，保留 Android 版的全部用户功能：十二时辰首页、时辰笺、农历月历、钟历、黄历详情和仪式计时器。两端保持一致的时辰规则、历法口径、内容和主要交互；iOS 界面使用 SwiftUI 与 iPhone 原生导航习惯。

App 离线运行，不要求账号、网络或位置权限。Android 工程继续保留，不迁移或重写。

## 页面与交互

### 十二时辰首页

- 显示十二地支时辰盘、实时晷针、当前时辰读数和固定诗句。
- 盘面支持点选时辰预览。真实当前时辰继续用克制的金色标记，预览时辰使用青绿色标记；晷针和“此刻”读数始终跟随真实时间。
- 保留“回到此刻”、夜间更点简化提示、日期入口和计时入口。
- 按设备本地民用时间计算时辰；每天 24 小时内晷针连续旋转。九十六刻、一刻十五分钟、初/正分段及更点时段沿用 Android 现有规则。

### 时辰笺

展示时辰名、别称、生肖、现代时间范围、生活意象、诗句全文、作者、篇名与出处。诗文沿用现有 Android 内容，不加入每日宜忌。

### 农历月历与黄历详情

- 月历以周一为首列，显示公历日、农历日，以及可用的节气或节日提示；切换月份、选择日期、回到今天均沿用 Android 已确认的规则。
- 日期简介展示农历年月日、生肖、干支、星期、节气/节日及简要宜忌。
- 黄历详情展示纳音、冲煞、彭祖百忌、方位、完整宜忌、吉神与凶神，并标注“传统民俗资料，仅供参考”和历法资料口径。
- 2025-01-01 至 2028-12-31 提供完整民俗字段。覆盖期外显示历法引擎能可靠提供的基础日期信息；不推测缺少的宜忌或神煞。引擎无法支持的日期保留公历月历，并显示资料不可用提示。
- 闰月、农历年边界、立春年柱边界、节气交接及日柱换日规则与 Android 一致。今天按设备本地时区计算；查看历史日期期间不因时区变化而静默改选日期。

### 钟历

- 与农历月历互相切换，保留相同月份和选中日期。
- 竖屏纵向排列时辰盘、单行当前读时和完整月历；横屏采用时辰盘与月历左右并列，不强制旋转。
- 钟历中的日期点击只改变选中高亮，不进入黄历详情；标题中的今日农历信息继续对应设备当前日期。

### 仪式计时器

- 提供“一刻（15 分钟）”“一炷香（30 分钟）”“半个时辰（60 分钟）”预设及开始、暂停、继续、重置。
- 默认静音；用户可选择随通知播放随 App 打包的钟磬音。
- 将预设、状态、剩余时间和结束时间保存到设备本机。运行时切到后台后安排 iOS 本地通知；暂停或重置时取消待发通知。回到前台或重新打开 App 时按保存的结束时间恢复状态。
- 首次开始计时前说明系统通知的用途，提供“开始并设置提醒”和“仅开始计时”两项选择；之后开始不重复打断用户。
- 选择设置提醒时请求通知权限。若用户拒绝或后来关闭通知，计时仍运行；App 前台刷新或下次打开时显示完成状态，并提供前往 App 通知设置的入口。
- iOS 通知由系统调度，设计不承诺 Android 精确闹钟同等的送达时刻。设备通知设置、专注模式及系统调度可能影响提醒表现。

## 视觉与导航

- 延续 Android 当前确立的近黑底 `#0F0E0D`、克制金色 `#D9A94B`、青绿色预览色 `#7FBFA4`、温和米白文字、宋体/衬线气质和充足留白。
- 按 iPhone 安全区布局，支持系统文字缩放和 VoiceOver 标签；使用 SwiftUI 原生导航与返回手势。保留竖屏堆叠及横屏双栏的钟历布局。
- 导航关系：时辰笺、月历、计时器由首页进入；钟历与农历月历互相切换；黄历详情仅从农历月历进入。返回时保留月历月份及选中日期。

## 技术架构

- 新增 `ios/Zichen/Zichen.xcodeproj` 和 `ios/Zichen/` 下的 Swift 源码及资源；iOS 工程与现有 Android `app` 并列维护。
- 使用 SwiftUI 实现页面与导航；将时辰计算、日期模型、历法适配器、计时状态和通知调度拆分为独立的 Swift 类型。视图只消费应用自有模型，不直接暴露第三方历法对象。
- 通过 Swift Package Manager 接入 6tail 的 `lunar-swift`，采用 1.1.8 版本，许可证声明为 MIT。将其输出映射为与 Android `LunarCalendarDay` 等价的应用模型，固定 Android 当前采用的福神方位流派和完整黄历覆盖期。参见 [6tail/lunar-swift](https://github.com/6tail/lunar-swift)、[版本记录](https://github.com/6tail/lunar-swift/blob/master/CHANGELOG.md) 和 [许可证](https://github.com/6tail/lunar-swift/blob/master/LICENSE)。
- 抽样对照 Swift 与 Android 的结果，至少涵盖普通日期、闰月、农历新年、立春前后、节气交接、2025–2028 年黄历字段及历法资料不可用边界。若库版本间存在结果差异，先调整适配规则或选择兼容版本，再将对应结果呈现给用户。
- 计时状态用 `Codable` 持久化到本机偏好存储；`UNUserNotificationCenter` 管理授权、通知的安排、取消与完成状态；前台按绝对结束时间更新显示。

## 错误与降级

- 历法单项字段缺失时显示“暂无资料”，不丢弃同日其他可用字段，也不补猜民俗数据。
- 日历引擎不支持某日期时保留公历网格与可用的实时时辰盘，并明确标注农历资料不可用。
- 通知权限不可用或调度失败时，计时状态仍由本机结束时间恢复；App 可见时显示完成状态。
- 本地音效缺失或系统未播放通知声音时，不影响计时完成状态和页面操作。

## 验收标准

- iOS 版包含 Android 对应的全部六类页面与已确认交互，中文文案及诗文内容一致。
- 首页实时盘、预览盘、刻读数、日期入口及更点提示符合现有 Android 口径。
- 两种日历的月份、选择、高亮、回到今天、页面切换和返回状态符合现有设计；黄历字段抽样与 Android 对齐，缺失数据不会伪造。
- 三种计时预设的开始、暂停、继续、重置、后台提醒、前台恢复、重新打开恢复、静音及钟磬选项按设计工作。
- 页面适配常见 iPhone 尺寸与系统安全区；竖屏钟历为纵向布局，横屏钟历为并列布局。
- 应用不请求账号、网络或位置权限；本地日历数据和计时状态不离开设备。

## 构建与验证边界

用户当前没有 Mac。当前工作环境是 Windows，因此本阶段可以提供 SwiftUI 源码、Xcode 工程文件和说明，但不能在本机运行 Xcode 构建、iOS 模拟器、签名或 iPhone 真机安装。最终构建和真机验收需要后续可用的 macOS/Xcode 环境与 iPhone；在完成前将其明确标记为未验证，不声称构建或真机验收通过。Apple 的[真机运行说明](https://developer.apple.com/documentation/Xcode/running-your-app-on-simulated-or-physical-devices)列出了 Xcode 与配对实体设备的运行流程。

本设计交付范围是仓库内的 iOS 工程源码和运行说明，不包括 TestFlight/App Store 发布、开发者账号配置或分发签名。
